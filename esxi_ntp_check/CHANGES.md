# esxi_ntp_check — правки v2 (логика проверок сохранена)

Скрипт
- storage: 0 только если известный адаптер не online (один из двух портов offline — тревога,
  как задумано). Все адаптеры `unknown` -> 1 (раньше ложный 0). Нет данных -> ошибка.
- Хост не `connected` (disconnected/notResponding) или свойство не прочитано -> ошибка
  (unsupported), а не 0: нет шторма из 5 ложных триггеров.
- `{#ESXIADDR}` теперь IP vmk0 (`summary.config.ipAddress` у HostConfigSummary не существует).
- `_find_host`: точное имя/IP; короткое имя только однозначное; убраны fallback «единственный
  хост» и поиск по подстроке.
- Кэш: TTL 900 c (> интервала айтемов), обновление под `flock`, уникальный tmp-файл.
- Общий дедлайн `ESXI_DEADLINE` (25 c) через SIGALRM; новый режим `hosts` (число хостов).
- Опциональная проверка TLS: `ESXI_CA_BUNDLE` (по умолчанию выключена, как раньше).
- Исправлен shim `ssl.wrap_socket` (`ciphers` не принимается SSLContext.wrap_socket); опечатки.

Шаблон
- Триггеры: `max(...,#2)=0` (2 подряд плохих значения, ~10 мин задержки), event_name с
  `{HOST.NAME}`, теги component/scope, manual_close.
- Самопроверка vCenter: айтем «ESXi hosts found in vCenter» + 2 триггера (nodata 30m, =0).
- Фильтр LLD по макросам, lifetime 7d, timeout 30s.
- Макросы `{$VMWARE.*}` по-прежнему берутся с мастер-хоста.

Не менялось: NTP = «настроен и ntpd запущен»; Power = политика из vCenter (High performance).
Не проверено: импорт в Zabbix 7.0 и работа против живого vCenter (нет доступа).

# v3 — шаблон "ESXi Health by vCenter" (вариант B + D)

Новый файл `Template ESXi Health by vCenter.yaml` (старый шаблон не тронут и работает с тем же
скриптом — старые режимы сохранены). Один внешний айтем `collect` раз в 5 минут отдаёт JSON по всем
хостам; LLD и все значения — зависимые (JSONPath). Недоступное значение опускается -> unsupported.

Остаётся из v2: NTP (настроен + ntpd), DNS, VMkernel, Storage-адаптеры, Power policy.
Добавлено (только то, чего нет в стандартном шаблоне VMware и SNMP по HPE):
- LLD аплинков vmnic (только порты, входящие в vSwitch/DVS): link up/down, скорость
  (порог `{$ESXI.NIC.SPEED.MIN}`, 0 = выкл.), триггер при down;
- LLD vSwitch/DVS: живые/назначенные аплинки, HIGH если живых 0;
- мультипасинг: число dead-путей (HIGH);
- датасторы, недоступные хосту (`accessible=false`, HIGH) + их имена;
- HA-агент (`dasHostState`): WARNING для isolated/partitioned/error/hostDown; хост вне HA — норма.
Намеренно НЕ добавлено: состояние хоста, overallStatus, uptime, датчики железа, ICMP, тревоги vCenter.

Проверено: py_compile, 15+11 unit-тестов (JSONPath каждого айтема на выходе collect, ключи
триггеров, uuid, valuemaps). НЕ проверено: импорт в Zabbix 7.0, работа против живого vCenter,
реальные имена свойств pyVmomi (`config.network.pnic/vswitch/proxySwitch`, `multipathInfo`,
`fileSystemVolume.mountInfo`, `runtime.dasHostState`).
Размер JSON ~490 байт/хост (200 хостов ≈ 99 КБ) — см. лимит значения типа text в вашей версии.

# v3.2 — подавление алертов при выводе хоста из кластера (A + C)
A. Флаг «алертить можно»
- Скрипт: `hosts.<имя>.alert` = 1, если хост connected и НЕ в Maintenance Mode (`runtime.inMaintenanceMode`),
  иначе 0. Недоступный хост тоже получает `alert: 0`, так что флаг есть всегда (в отличие от остальных значений).
- Шаблон: служебный элемент «Alerting enabled for …» в каждом правиле LLD (hosts / pnic / sw: триггер-прототип
  может ссылаться только на элементы своего правила). Все 13 триггер-прототипов начинаются с
  `min(<флаг>,{$ESXI.ALERT.HOLDDOWN})=1 and (...)`. HOLDDOWN по умолчанию 10m = пауза после выхода из MM.
  Триггеры сборщика (vCenter недоступен, 0 хостов) не подавляются.
- При переходе флага в 0 триггер становится ложным, и проблема закрывается сама.
C. Потерянные хосты
- Правила LLD: `enabled_lifetime_type: DISABLE_IMMEDIATELY`, удаление через 7d (история сохраняется на время
  переустановки ESXi / замены железа). Хост, снова найденный в vCenter, включается обратно.
Тесты: флаг в collect, защита и локальность ключей каждого триггера, настройки lifetime (+2 мутации проверены).

Требует проверки на тестовом Zabbix 7.0:
1. Импорт (`enabled_lifetime_type` записан по памяти формата 7.0).
2. `A and (B)`, где B на unsupported-элементе: должно быть ложным при флаге 0 (флаг поставлен первым).
3. Закрываются ли уже открытые проблемы при отключении потерянных элементов (DISABLE_IMMEDIATELY).

# v3.3 — исправления по code-review (пункты 1–5)
1. Lock/кэш: имя файлов содержит uid; `.lock` открывается `os.open(..., 0o600)` и его сбой не фатален
   (раньше `PermissionError`, если файл создан другим пользователем, например при ручном запуске под root).
2. Дедлайн: `_on_deadline` завершает процесс через `os._exit(1)`; пул потоков `QueryDateTime`
   закрывается `shutdown(wait=False, cancel_futures=True)` (раньше ждал всю очередь).
3. LLD портов/свитчей: для хостов не в `connected` строки берутся из прошлого кэша (`_carry_lld`),
   значения не отдаются. Строки больше не пропадают при кратком обрыве, элементы не отключаются/включаются.
4. Новые свойства читаются отдельной пачкой (`_batch_optional`); при сбое — повтор по одному свойству,
   неверное имя попадает в warn. Новый элемент «Collector warnings» + триггер WARNING (`length(...)>0`):
   тихой потери данных больше нет, в том числе при откате на медленный режим.
5. NTP: ссылка `dateTimeSystem` / `dateTimeInfo` не прочитана -> `None` (unsupported), а не ложный 0.
Тесты: 25 + 20; поломка каждого исправления по очереди ловится (кроме uid в имени кэша: тесты идут под root).
Не менялось и не проверено на живом vCenter: см. v3.2.

# v3.5 — исправления по code-review дашборда (пункты 1–3)
1. `warn` в JSON сборщика теперь `"OK"`, если предупреждений нет (раньше пустая строка), `ds_names` — `"-"`.
   Триггер «Collector reports missing vCenter data»: `last(...)<>"OK"`; плитка дашборда мапит `OK` -> зелёный.
   Причина: Zabbix может не сохранить пустое значение, и последнее непустое предупреждение осталось бы навсегда.
   Не проверено на живом Zabbix 7.0.
2. `bars()` перенесён из `vmware/tools/gen_nsx_dashboard.py` в общий `grafana/tools/gen_health_dashboard.py`;
   генераторы NSX и ESXi берут его оттуда (дашборды NSX и 3PAR после переноса побайтно не изменились).
3. Хелперы плиток: `light`, `count_tile`, `count_rows` сведены в один `light(..., colour=, keep=)` поверх
   `problems_tile` (получил параметры `colour` и `keep`). Все остальные панели дашборда ESXi остались идентичными.
Тесты: контроль «нет пустых строк», триггер сравнивает с `"OK"`, отбор фильтра по `id`, а не по индексу,
генератор не импортирует модуль NSX. Из семи замечаний ревью не вошли 4–7 (кроме индекса в тестах, он поправлен заодно).
